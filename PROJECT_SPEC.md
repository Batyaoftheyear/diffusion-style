### 5. Используемые модели

Основная модель:

`stable-diffusion-v1-5/stable-diffusion-v1-5`

ControlNet:

`lllyasviel/control_v11p_sd15_canny`

IP-Adapter:

`h94/IP-Adapter`

Использовать совместимые веса IP-Adapter для SD 1.5 и соответствующий image encoder.

Перед реализацией проверить точные идентификаторы, расположение весов и совместимость с выбранной версией Diffusers.

Основной генерационный пайплайн:

**Stable Diffusion 1.5 + ControlNet Canny + IP-Adapter**

ControlNet получает карту контуров исходной фотографии.

IP-Adapter получает художественное изображение-референс.

Stable Diffusion генерирует новую фотографию, стремясь сохранить исходную композицию и передать художественный стиль.

Для генерации использовать текстовый промпт, описывающий содержание исходного изображения.

Не использовать img2img в качестве дополнительного механизма сохранения исходной фотографии: композиция должна передаваться именно через ControlNet Canny.

В будущем планируется заменить IP-Adapter на обученную LoRA при сохранении той же базовой SD и ControlNet.

Поэтому реализацию baseline нужно организовать так, чтобы генерационный код впоследствии можно было расширить.

При этом **не нужно реализовывать ветвь LoRA на первом этапе**.

### 7. Воспроизведение baseline

Это основной технический результат первого этапа.

Реализовать инференс Stable Diffusion 1.5 + ControlNet Canny + IP-Adapter.

Входные данные:

1. Текстовый промпт.

3. Художественный референс.
4. Начальный латентный шум.
5. Параметры генерации.

Результат — стилизованная фотография 512×512.

Начальная конфигурация:

```yaml
resolution: 512
num_inference_steps: 30
guidance_scale: 7.5
controlnet_conditioning_scale: 1.0
ip_adapter_scale: 0.6

scheduler: DDIM
seed: 42

canny_low_threshold: 100
canny_high_threshold: 200

dtype: float16
```

Эти значения являются отправной точкой, а не утверждением об их оптимальности.

Дополнительные seed запланировать для второго этапа.

Не выполнять необязательный перебор гиперпараметров.

### 8. Метрики и оценка baseline

Необходимо определить протокол оценки и реализовать базовые метрики, чтобы включить реальные численные результаты в PDF-отчёт.

#### 8.1. Сохранение композиции

Использовать Canny edge matching.

Для исходного и сгенерированного изображения вычислять карты контуров с одинаковыми параметрами.

Рассчитывать:

- Edge precision.
- Edge recall.
- Edge F1-score.

Предусмотреть небольшой фиксированный допуск на смещение контуров, чтобы не штрафовать за незначительные геометрические отклонения.

Задокументировать способ сопоставления и размер допуска.

Указать ограничение: художественные текстуры могут создавать дополнительные контуры, поэтому Edge F1 не является идеальной мерой сохранения композиции.

#### 8.2. Сохранение содержания

Использовать предобученную DINOv2.

Для исходного и сгенерированного изображения извлекать глобальные визуальные признаки.

Рассчитывать cosine similarity.

Для всех изображений использовать одинаковые preprocessing, модель и настройки.

Задокументировать конкретную модель DINOv2 и способ формирования embedding.

Указать, что cosine similarity отражает приближённое семантическое сходство.

#### 8.3. Соответствие стилю

Основной подход на первом этапе — визуальный анализ.

Создать сравнительные изображения, позволяющие оценить, насколько результат воспроизводит цветовую палитру, фактуру и художественные признаки выбранного стиля.

Не создавать искусственный style score без обоснования.

Для последующего этапа описать план экспертной оценки по шкале 1–5.

#### 8.4. Вычислительные показатели

Дополнительно измерять:

- время генерации одного изображения;
- пиковое потребление видеопамяти;
- число шагов инференса.

При измерении времени GPU-инференса использовать синхронизацию CUDA.

Отделять время загрузки моделей от времени генерации.

#### 8.5. Итоговые результаты

Для 24 изображений сформировать таблицу метрик.

Рассчитать средние значения и стандартные отклонения.

Указывать, что при одном seed на изображение разброс характеризует вариацию между изображениями, а не устойчивость к случайному шуму.

Сохранить результаты в CSV.

Подготовить компактную сводную таблицу для PDF-отчёта.

### 10. План экспериментов второго этапа

**Здесь требуется только планирование, без реализации.**

В `docs/stage2_plan.md` описать экспериментальные оси и гипотезы.

#### 10.1. Ранг LoRA

Планируемые значения:

- 4;
- 8;
- 16.

Гипотеза: увеличение ранга может улучшить воспроизведение сложных стилевых признаков, однако рост числа параметров не обязательно обеспечит дальнейшее улучшение качества.

#### 10.2. Коэффициент применения LoRA

Планируемые значения:

- 0.5;
- 0.8;
- 1.0.

Гипотеза: более высокий коэффициент усиливает влияние обученного стиля, но может снижать сохранение содержания исходной фотографии.

#### 10.3. Коэффициент IP-Adapter

Планируемые значения:

- 0.3;
- 0.6;
- 0.9.

Гипотеза: повышение коэффициента усиливает влияние стилевого референса, но может приводить к переносу нежелательных содержательных признаков.

#### 10.4. Динамические коэффициенты

Предусмотреть сравнение:

- constant;
- linear increase;
- linear decay.

При наличии ресурсов — cosine schedule.

Гипотеза: изменение силы стилевого условия в процессе денойзинга может изменить баланс сохранения композиции и выраженности художественного стиля.

Не утверждать заранее, какая схема будет лучше.

#### 10.5. Экспериментальный протокол

Запланировать:

- pilot: 6 фотографий, 1 seed;
- основное сравнение: 24 фотографии, 3 seed.

При сравнении LoRA и IP-Adapter должны быть одинаковыми:

- исходные фотографии;
- Canny-карты;
- базовая SD;
- ControlNet;
- промпты;
- negative prompts;
- scheduler;
- количество шагов;
- CFG;
- разрешение;
- ControlNet scale;
- начальные latents.

Описать, что LoRA и IP-Adapter получают стилевую информацию разными способами, поэтому условия сравнения не являются полностью одинаковыми по объёму стилевой информации.

Не проводить запланированные эксперименты сейчас.
