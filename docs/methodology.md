# Данные, воспроизводимость и протокол оценки

## Состав данных

Источник стиля — [huggan/wikiart](https://huggingface.co/datasets/huggan/wikiart), revision d559852d2b232e0fcf195e775866964f0564f2b5. Класс Impressionism определяется через ClassLabel из ответа API, а не по неподтверждённому числовому индексу. Читаются первые 1500 строк каталога через [Dataset Viewer /rows](https://huggingface.co/docs/dataset-viewer/en/rows), по 100 за запрос. Загружаются только метаданные кандидатов и отдельно выбранные изображения, не многогигабайтные parquet shards. Ответ обязан иметь X-Revision, равную закреплённой revision. При изменении серверного каталога подготовка останавливается.

Сетевые ошибки 408/429/500/502/503/504 повторяются до шести раз с растущими паузами и учётом Retry-After (максимум 60 секунд ожидания за попытку). Завершившийся неудачей запрос даёт явное сообщение о недоступном источнике. Проверка TLS не отключается. При построении каталога страницы с совпадающей закреплённой revision используются из кэша без ограничения в пять минут; для временных image URL сохраняется короткий срок актуальности. Это меняет только транспорт и продолжение работы, а не набор кандидатов или порядок отбора.

Кандидаты сортируются по SHA-256 от пары seed и row_idx. Порядок не зависит от глобального RNG или хеш-рандомизации Python. В порядке обхода исключаются совпадающие RGB pixels, совпадающие подготовленные pixels и dHash с расстоянием Хэмминга ≤ 2. Это эвристика близких копий, которая может ошибаться; её порог фиксируется. Первые пять допустимых картин — held-out references, остальные 70 — future_train; всего 75. Основной референс — первый reference. Исключение дубликатов проводится до разбиения. Референсы не используются для будущего обучения.

Названия работ в зеркале отсутствуют: не выдумываем их. Сохраняются row_idx, artist, genre, style, revision и ссылка на строку каталога. Исходник означает доставленное изображение зеркала; оно не обязательно совпадает с исходным музейным сканом. Captions картин — шаблон по жанру, без выдумывания предметных деталей. Перед будущим обучением требуется ручной просмотр качества, однородности и captions.

COCO: [phiyodr/coco2017](https://huggingface.co/datasets/phiyodr/coco2017), revision 036f3f8291db64d17faad9b09e59dd30bb65c4d7. Streaming читает только малый validation-каталог URL и аннотаций; фотографии загружаются по 24 официальным coco_url. Из-за несоответствия HTTPS-сертификата доменного alias загрузка идёт через тот же публичный S3-бакет по пути https://s3.amazonaws.com/images.cocodataset.org/val2017/<ID>.jpg с обычной TLS-проверкой. Исходный coco_url и фактический download_url сохраняются раздельно. Каждая из шести групп (люди, животные, город, природа, предметы, интерьеры) содержит четыре уникальных фото. Группы определяются документированными regex в src/data.py по всем captions, а не официальной разметкой COCO categories. При пересечении групп ID не повторяется. Результат идёт раундами по группам, поэтому первые шесть фото покрывают их все. Это целевой детерминированный отбор, не оценка всего распределения COCO.

Промпт — caption с минимальным annotation ID. Сохраняются все исходные captions, выбранный caption_id, image_id, URL, license_id, flickr_url и scene_group. После просмотра результатов менять промпты и тестовую выборку нельзя без нового протокола.

## Преобразования и контроль

EXIF orientation → RGB → центральный ImageOps.fit с LANCZOS до 512 × 512. Пропорции не искажаются; центральная обрезка может потерять важные объекты, поэтому preview просматривается перед GPU-запуском. Затем grayscale и Canny с 100/200, apertureSize=3, L2gradient=False; карта сохраняется в RGB PNG. Размеры, SHA-256, разбиения и все пути проверяются. Пути из metadata обязаны оставаться внутри корня артефактов.

Каталог data/<data_id>/ определяется настройками подготовки, версиями NumPy/Pillow/OpenCV и DATA_VERSION. В нём сохраняются оригиналы, prepared, canny, captions, checkpoint отдельного item, manifests и frozen catalogue. Законченная подготовка повторно проверяет файлы без обращения к сети. Частичная подготовка продолжает те же детерминированные выборки; изменённый удалённый оригинал не должен заменять зафиксированный SHA. При изменении алгоритма подготовки необходимо увеличить DATA_VERSION.

[Модель ControlNet](https://huggingface.co/lllyasviel/control_v11p_sd15_canny) предназначена для SD 1.5; [encoder config](https://huggingface.co/h94/IP-Adapter/blob/main/models/image_encoder/config.json) проверен отдельно.

Seed 42 применяется отдельным CPU torch.Generator к каждому тензору формы 1 × 4 × 64 × 64, dtype float32. В текущем протоколе все фото получают один и тот же начальный шум; это сознательно выбранное парное условие. NPY сохраняет реальные значения, затем тензор приводится к float16. DDIM eta = 0; scheduler config записывается полностью. Детерминированные алгоритмы включены, TF32 и cudnn benchmark выключены. [Ограничения межплатформенной воспроизводимости PyTorch](https://docs.pytorch.org/docs/stable/notes/randomness.html) сохраняются.

run_id учитывает конфигурацию, hashes manifests, генерационный код и версии окружения/GPU. В каждой metadata присутствуют фото, референс, prompts, seed, models, параметры, среда, замеры и SHA результата/шума. Проверка cache не ограничивается существованием PNG. Изменённые входы или настройки создают другой прогон; повреждённый результат повторяется. Модели не загружаются, если все нужные результаты уже проверены. Одновременные записи из нескольких Colab runtimes в один каталог не поддерживаются.

## Метрики

Для S — исходных контуров, G — контуров результата — используется квадратное расширение радиуса δ = 2, то есть расстояние Чебышёва. Precision = |G ∩ dilate(S)| / |G|; recall = |S ∩ dilate(G)| / |S|; F1 — гармоническое среднее. Оба знаменателя относятся к своим картам: они не заменяются одним общим числом совпадений. Это many-to-many matching; более плотные границы могут получать завышенное совпадение. При нулевом знаменателе соответствующая величина равна 0; обе пустые карты дают 0, поскольку свидетельства сохранённой структуры нет. Все значения в [0,1]. Пороги Canny и допуск фиксированы для всех условий.

DINOv2: [facebook/dinov2-base](https://huggingface.co/facebook/dinov2-base), CLS последнего hidden state без классификационной головы; L2-normalized FP32 embedding. AutoImageProcessor с use_fast=False, параметры и revision записываются. Cosine сравнивает подготовленное исходное фото и результат, а не Canny. Это приближённое семантическое сходство, чувствительное и к внешнему виду. DINO считается отдельным процессом после выгрузки генерационных моделей.

Таймер охватывает вызов пайплайна: encoder, UNet, ControlNet, VAE, safety checker и transfers при offload. CUDA синхронизируется до/после; загрузка моделей измеряется отдельно. Reset peak memory stats выполняется перед каждой генерацией; allocated и reserved сохраняются в МиБ. Первая генерация может быть медленнее из-за прогрева. Flag safety checker останавливает запуск и не считается успешной стилизацией; отключение проверки не выполняется автоматически.

Среднее, выборочное SD (ddof=1) и фактическое n успешных изображений сохраняются в CSV/JSON; на одном наблюдении SD в служебных тестах принят равным 0. Разброс на этапе 1 — между фотографиями при одном seed. Оценка стиля — просмотр palette/texture/brushwork по сравнительным таблицам, без искусственного style score. Шесть первых примеров — заранее заданные, не выбранные по лучшим метрикам. В отчёт включены первые два примера; полная таблица первых шести сцен сохранена отдельно.

## Явные пропуски без повторной генерации

Если сохранены все остальные результаты, подтверждённое логом срабатывание постфильтра можно отметить через finalize_run.py --skip-photo <ID> --reason safety_checker. Эта команда не меняет конфигурацию, генерационный код, run_id, исходные фото, prompts или seed. Она проверяет готовые PNG/latents, записывает явную причину пропуска в skips/, проверяет охват всех 24 входов и обновляет только служебную сводку. Существующие успешные изображения нельзя объявить пропусками.

Успех и обработка разделены: при 23 PNG и одном пропуске complete=false, processed_complete=true. Метрики используют 23 успешные пары, CSV/PDF указывают один пропуск и его причину. Чёрные заглушки не оцениваются, другие фото вместо пропущенного не подбираются. Пропуск может смещать агрегированные показатели; при сравнении методов следует использовать согласованные пары и отдельно сообщать долю неуспехов. Проверка конфигурации, hashes и кода генерации сохраняется: результатов другого прогона здесь не подмешивают.

## Источники и правовой статус

- [SD 1.5](https://huggingface.co/stable-diffusion-v1-5/stable-diffusion-v1-5): CreativeML OpenRAIL-M; репозиторий является зеркалом исходной модели.
- [ControlNet](https://huggingface.co/lllyasviel/control_v11p_sd15_canny): карточка описывает CreativeML OpenRAIL-M, metadata помечена openrail.
- [IP-Adapter](https://huggingface.co/h94/IP-Adapter) и [выбранная конверсия DINOv2](https://huggingface.co/facebook/dinov2-base): Apache-2.0 по карточкам моделей.
- [WikiArt](https://huggingface.co/datasets/huggan/wikiart): некоммерческое исследовательское использование по карточке; права на изображения принадлежат авторам. Это не подтверждение единой свободной лицензии и не индивидуальная юридическая проверка каждой картины. Не публиковать dataset вместе с кодом.
- [COCO terms](https://cocodataset.org/#termsofuse): права на фотографии индивидуальны. Сохраняются оригинальные license_id и Flickr/COCO URL; лицензия annotation-каталога не переносится автоматически на изображения.

Завершённый запуск на Tesla T4: run_id c66b0a9fe8ce4d583cfd, 23 успешных результата и один явный пропуск. Параметры и метрики сохранены в baseline/run.json, baseline/summary.json и baseline/metrics.csv; результаты и ограничения разобраны в отчёте.
