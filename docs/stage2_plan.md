# План второго этапа — без реализации

Этап 1 не включает тренировочный скрипт, DataLoader LoRA, загрузку обучающих моделей, расписания коэффициентов и перебор параметров. Ниже зафиксирован только план.

## Обучение

Использовать [официальный пример Diffusers](https://github.com/huggingface/diffusers/blob/v0.35.2/examples/text_to_image/train_text_to_image_lora.py) после отдельной проверки его зависимостей. Обучать только LoRA в attention-проекциях UNet; заморозить базовые UNet, VAE и text encoder. ControlNet и IP-Adapter в обучении отсутствуют. Выбор target_modules нужно закрепить перед первым обучением.

Стартовые параметры: 512 × 512, rank 8, batch size 1, gradient accumulation 4, FP16, gradient checkpointing, learning rate 1e-4, constant LR, 1000 optimizer steps, seed 42. Gradient accumulation даёт эффективный batch 4 на одном GPU; 1000 optimizer steps означают 4000 микробатчей. При 70 картинах это много повторных предъявлений, поэтому бюджет не следует считать заведомо безопасным от переобучения.

Batch size 1 ограничивает VRAM. FP16 уменьшает память активаций; gradient checkpointing экономит её ценой повторного вычисления. Learning rate задаёт величину обновления, число optimizer steps — длительность адаптации. Проверить loss и визуальные результаты через регулярные интервалы, не выбирать модель по финальным 24 фото.

Сравнить ранги 4, 8, 16 на одной коллекции и captions, с одинаковым числом optimizer steps, target_modules и остальными гиперпараметрами. Для отделения эффекта ёмкости от масштаба нормировки поддерживать постоянное отношение alpha/r (предварительно alpha = r). Training alpha и коэффициент применения при генерации — разные параметры.

Сохранять веса адаптера, optimizer, LR scheduler, scaler, состояние RNG и номер шага; проверять resume на коротком запуске. Хранить чекпоинты и loss в Drive. При изменении конфигурации создавать новый прогон.

## Исследование генерации

1. Статические веса LoRA: 0.5, 0.8, 1.0. Веса IP-Adapter: 0.3, 0.6, 0.9. Контроль ControlNet остаётся 1.0.
2. Pilot: первые шесть сцен фиксированного COCO-отбора, seed 42. За один опыт менять один фактор.
3. Constant, linear increase, linear decay; cosine — при наличии ресурсов. Для сравнения временного распределения поддерживать одинаковый средний вес, например constant s против линейных 0 → 2s и 2s → 0. Если вводится ограничение максимального веса, учитывать его и вновь уравнивать средние значения.
4. Установить начальный вес до первого вызова UNet. Callback конца шага k должен задавать вес для k + 1. Хранить реальные применённые веса; проверить их воздействие на настоящем пайплайне.
5. Подтверждение: 24 фото × seeds 42, 123, 777. Три seed оценивают вариацию шума, фотографии остаются единицами парного сравнения. Метрики усреднять сначала внутри фотографии, затем между фотографиями; доверительные интервалы, если нужны, строить по фотографиям.

Для LoRA и IP-Adapter совпадают SD, ControlNet, scheduler, resolution, шаги, CFG, Canny, содержание промптов, negative prompt и исходные латенты. Сначала выгружать один адаптер либо создавать отдельный пайплайн: одновременное воздействие методов не является независимым сравнением.

## Экспертная оценка и риски

Показать исходник, стилевые референсы и результаты с анонимными кодами в перемешанном порядке. Отдельные шкалы 1–5: соответствие стилю (палитра/фактура/мазки), сохранение содержания, композиция, выраженность артефактов. Зафиксировать инструкции оценщикам и направление каждой шкалы; не объединять их в произвольный единый style score. Сохранять оценки каждого эксперта и межэкспертное согласие. До начала оценивания определить число экспертов и доступный бюджет.

Риски: стилевое разнообразие WikiArt, недостаточные captions, доминирование мотивов художника, переобучение, перенос объектов IP-Adapter, ограничение T4, прерывания Colab, нестабильность динамических весов и смещения автоматических метрик. При неоднородности коллекции сузить её до одного художника/согласованной группы до обучения. Изменение теста после просмотра результатов недопустимо.

Ожидаемый результат — набор сопоставимых генераций и измерений с анализом компромисса между содержанием и стилем. Улучшение какого-либо метода или расписания не гарантируется.
