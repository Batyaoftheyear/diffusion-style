# План второго этапа

Цель следующего этапа — обучить стилевую LoRA, сравнить её с IP-Adapter и исследовать влияние ранга, силы стилевого условия и расписания коэффициентов.

## Обучение LoRA

Для обучения планируется использовать [пример Diffusers](https://github.com/huggingface/diffusers/blob/v0.35.2/examples/text_to_image/train_text_to_image_lora.py). LoRA подключается к attention-проекциям UNet. Базовые UNet, VAE и текстовый энкодер заморожены; ControlNet и IP-Adapter используются только при генерации.

Начальные параметры: 512 × 512, ранг 8, batch size 1, gradient accumulation 4, FP16, gradient checkpointing, learning rate 1e-4, постоянная скорость обучения, 1000 шагов оптимизатора, seed 42. Список `target_modules` фиксируется перед обучением.

Batch size 1 и FP16 ограничивают расход видеопамяти. Накопление градиентов даёт эффективный batch size 4, а gradient checkpointing сокращает память активаций за счёт повторных вычислений. При таком накоплении 1000 шагов оптимизатора соответствуют 4000 микробатчам. Для 70 картин это много повторных предъявлений, поэтому в ходе обучения нужно отслеживать loss и результаты на отложенных примерах.

Ранги 4, 8 и 16 сравниваются на одной коллекции с одинаковыми описаниями, слоями адаптации и числом шагов оптимизатора. Отношение α/r сохраняется постоянным; начальный выбор — α = r. Это позволяет отделить влияние ранга от нормировки обновления. Для learning rate и длительности обучения сначала проверяется исходная конфигурация; при признаках нестабильности или переобучения параметры уточняются по отложенным примерам.

Контрольные точки содержат веса LoRA, состояния оптимизатора, планировщика скорости обучения, FP16 scaler, генераторов случайных чисел и номер шага. Короткий запуск проверяет сохранение и восстановление обучения. Контрольные точки и loss хранятся в Drive.

## Эксперименты с генерацией

1. Сравнить постоянные веса LoRA 0.5, 0.8 и 1.0 и веса IP-Adapter 0.3, 0.6 и 0.9. Коэффициент ControlNet оставить равным 1.0.
2. Провести предварительные эксперименты на первых шести сценах COCO при seed 42, меняя по одному фактору за запуск.
3. Сравнить постоянный вес s, линейное увеличение 0 → 2s и линейное уменьшение 2s → 0. Средняя сила условия должна совпадать. Если вводится ограничение максимального веса, среднее пересчитывается с учётом ограничения.
4. Задать вес до первого вызова UNet и записывать коэффициент каждого шага. Обновление через callback конца шага k должно применяться на шаге k + 1.
5. Выполнить итоговое сравнение на 24 фото с seed 42, 123 и 777. Сначала усреднить метрики по seed внутри фотографии, затем по фотографиям. Единицей парного сравнения остаётся фотография; доверительные интервалы рассчитываются по фотографиям.

Для обеих ветвей сохраняются SD, ControlNet, планировщик, разрешение, число шагов, CFG, Canny-карты, промпты и начальные латенты. Каждый метод запускается отдельно. LoRA получает коллекцию при обучении, IP-Adapter — один фиксированный референс при генерации; это различие сохраняется в протоколе.

## Визуальная оценка

Исходники, референсы и результаты показываются с анонимными обозначениями в перемешанном порядке. Соответствие стилю, сохранение содержания, композиция и выраженность артефактов оцениваются отдельно по шкалам 1–5. Для каждой шкалы заранее задаются критерии и направление оценки. Сохраняются индивидуальные оценки и согласованность экспертов. Число оценщиков определяется до начала оценки с учётом доступного времени.

## Риски и ожидаемые результаты

Основные риски — неоднородность коллекции, недостаточно точные описания картин, переобучение LoRA и перенос объектов из референса IP-Adapter. Перед обучением нужно просмотреть картины и описания; при необходимости сузить коллекцию до одного художника или визуально близких работ. Тестовые фото и промпты сохраняются на протяжении сравнения.

Лимиты T4 и прерывания Colab ограничивают число экспериментов. Сохранение контрольных точек и результатов позволяет продолжать работу после остановки. Автоматические метрики сопоставляются с визуальной оценкой, поскольку совпадение контуров или DINO-признаков не описывает качество стиля полностью.

Результатом этапа станет сравнение методов при одинаковых условиях генерации и анализ того, как параметры меняют соотношение между стилем, содержанием и композицией.
